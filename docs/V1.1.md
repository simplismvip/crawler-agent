# 爬虫 AI Agent (V1.1 MVP) 开发实施方案

本方案是 V1 的落地修订版。核心目标不变：**打通端到端闭环**——一个带 2 个强类型工具的 function-calling 循环，事件流同时喂 CLI 和 Web SSE，完成公开网页的检索与结构化抓取。

V1.1 不追求仿 Gemini 的完整产品壳，也不做通用爬虫平台。

## 0. 范围

### 做

- 原生 OpenAI 兼容 **function calling**（不是 ReAct 文本协议）。
- 两个工具：`search_web`、`scrape_page`。
- 同一条异步事件生成器，CLI 与 Web 只是两种渲染器。
- 基础公开网页：HTTP(S) 正文抽取；JS 页可降级浏览器。
- 熔断、SSRF 防护、超时、体积上限、客户端断开取消。

### 明确不做（推迟到 V2）

- Crawl4AI、Claude 双供应商、登录墙、绕过反爬。
- 会话持久化、多用户、真实历史列表。
- 多页并行抓取、一次并行执行多个工具、站点级爬虫调度。
- Gemini 级视觉打磨（胶囊输入框、完整侧边栏交互）。

### 当前落地默认（V1.1 先用着）

这两项与 V1 初稿（搜索 Tavily → DuckDuckGo、模型默认 `gpt-4o-mini`）不同，以实际部署为准，**暂不做成可切换产品能力**：

| 项 | 当前默认 | 后续（V1.2 / V2） |
| --- | --- | --- |
| 搜索 | `search_web` 主路径为树莓派 SearXNG（Tailscale：`http://100.120.153.107:8888`，环境变量 `SEARXNG_BASE_URL`） | 可配置多家搜索：SearXNG / Tavily / DuckDuckGo 等，按环境变量或设置项切换 |
| 模型 | MiniMax-M3，经 OpenAI 兼容接口（`MINIMAX_API_KEY` + `https://api.minimax.cn/v1`） | 可配置其他 OpenAI 兼容网关与模型名，不改 Agent 循环 |

搜索优先级（代码已实现，当前只主动用第一条）：**SearXNG → Tavily（`SEARCH_API_KEY`）→ DuckDuckGo**。本机不强制 Docker 起 SearXNG。

模型侧仍只接 **一套** OpenAI 兼容客户端；换厂商等于换 `base_url` / `api_key` / `model`，V1.1 不并行接入 Claude 原生协议。

## 1. 系统总体架构与数据流

系统由 **Agent 引擎**、**Skill 执行器**、**FastAPI 网关** 与 **双端渲染（CLI / Web）** 构成。CLI 不再绕过网关逻辑：两端都消费 `engine.run()` 产出的事件。Web 经 HTTP；CLI 可直接调用同一生成器，便于本地调试，但事件 schema 必须一致。

```
  CLI (Rich)                         Web (Next.js)
       │                                  │
       │  直接消费事件生成器                 │  POST /api/chat  + SSE
       │                                  │
       └──────────────┬───────────────────┘
                      ▼
              FastAPI 仅作为 Web 适配器
              （鉴权、SSE 包装、断开取消）
                      │
                      ▼
              Agent 引擎（function calling 循环）
              - 组装 messages + tools schema
              - max_llm_rounds = 8
              - max_tool_calls = 4
              - 超限强制总结
                      │
          ┌───────────┴───────────┐
          ▼                       ▼
     LLM API                 Skill 执行器
     OpenAI 兼容                 Skill 执行器
     当前：MiniMax-M3            1. search_web（SearXNG）
     （流式 token /              2. scrape_page
       tool_calls）               httpx 默认
                                  Playwright 降级
                      │
                      ▼
              事件生成器（唯一真实来源）
              token / tool_start / tool_end / ping / error / done
```

真实顺序是**串行观察循环**，不是 LLM 与 Skill 并行：

1. 调 LLM（流式）。可见文本走 `token`；工具参数分片在引擎内缓冲，不发事件。
2. 当前轮 `tool_calls` **全部收齐**后，对每个调用依次处理：`args` 可解析则 `tool_start` → 执行 → `tool_end`；不可解析则只发 `tool_end(error)`，仍必须写回对应 `role: "tool"`。
3. 把本轮完整的 `assistant` 消息（含全部 `tool_calls`）**原样**压入上下文，再紧跟**每一条**对应的 `role: "tool"` 消息，然后进入下一轮 LLM。
4. 直到模型不再调工具、或触发熔断后强制总结。无论成败，最后发 `done`。

## 2. 核心模块设计与职责

### 模块 A：Skill 工具执行层（`backend/skills/`）

入参、出参必须是 Pydantic 模型，并由模型**自动生成 JSON Schema** 注册给 LLM。禁止把列表 `str()` 后再交给模型解析。

#### `search_web`

```python
class SearchWebInput(BaseModel):
    query: str
    max_results: int = 3  # 上限夹紧到 1~5

class SearchHit(BaseModel):
    title: str
    url: str
    snippet: str

class SearchWebOutput(BaseModel):
    query: str
    results: list[SearchHit]
```

- **作用**：为后续抓取提供候选 URL。
- **当前实现**：主路径 **SearXNG**（`SEARXNG_BASE_URL`）。未配置时才用 Tavily（`SEARCH_API_KEY`），再否则 DuckDuckGo 非官方库（单测网络失败允许 skip）。
- **后续**：搜索后端可配置，不写死某一家。
- **约束**：`max_results` 默认 3；不在工具内二次抓页。

#### `scrape_page`

```python
class ScrapePageInput(BaseModel):
    url: str

class ScrapePageOutput(BaseModel):
    url: str
    title: str = ""
    markdown: str = ""
    truncated: bool = False
    error: str | None = None  # 失败时必填，markdown 可为空
```

- **作用**：抓取目标页，清洗为主内容 Markdown。
- **实现分层（两段式抽取，浏览器是第三档）**：
  1. `httpx` 取 HTML。
  2. **主抽取**：`trafilatura`（或 readability）抽正文并转 Markdown。
  3. **列表页回退**：若结果为 `None` 或正文少于 200 字符，不要启动浏览器。改用 `markdownify`（或 BeautifulSoup 保链转换）把 `body` 转成 Markdown，**保留 `<a>`、列表、表格**。HN 这类高结构、低段落密度页面走这一档。
  4. **浏览器降级**：仅当回退后仍过短，且页面像 JS 壳（几乎无链接/正文、大量空节点）时，才用 Playwright 渲染，然后重复 2→3。浏览器必须跑在独立线程或进程，**禁止阻塞** Agent 的 async 生成器。
  5. Crawl4AI **不进 V1.1 依赖**。
- **禁止**：把「trafilatura 抽空」直接当成「需要 Playwright」。那会让用例 1 又慢又不稳定。
- **截断**：按 tokenizer 估算，正文上限 **4000 tokens**（约 12k 字符作兜底）。超限设 `truncated=true`，保留开头主内容。
- **回给 LLM 的内容**：`ScrapePageOutput` 的 JSON；若 `markdown` 仍过长，引擎层可再压成「标题 + 前 3000 tokens」。
- **回给前端的内容**：见 `tool_end.preview`，不是全文。

#### 抓取安全与礼貌（必须实现）

| 规则 | 要求 |
| --- | --- |
| 协议 | 只允许 `http` / `https` |
| SSRF | 解析 DNS 后拒绝回环、私网、链路本地、云 metadata（含 `169.254.169.254`、IPv6 等价地址） |
| 跳转 | 最多跟随 3 次 redirect，每次目标都要重做 SSRF 检查 |
| 超时 | 连接 + 读取合计 15s |
| 体积 | 下载硬上限 2MB |
| 并发 | 全局同时抓取 = 1；同域最小间隔 1s |
| UA | 固定可识别 UA，例如 `CrawlerAgent/1.1 (+local-mvp)` |
| 范围 | 不处理登录墙，不绕过验证码/反爬；失败就失败 |

V1.1 默认只绑定 `127.0.0.1`。若对局域网开放，必须加 `API_TOKEN` 头校验。

### 模块 B：Agent 核心引擎（`backend/agent/`）

- **架构**：原生 function calling 循环。不引入 LangGraph / 全家桶；不使用「Thought/Action」文本 ReAct。
- **模型（当前）**：MiniMax-M3，OpenAI 兼容（`MINIMAX_API_KEY` 或 `OPENAI_API_KEY`，`OPENAI_BASE_URL`/`MINIMAX_BASE_URL`，`OPENAI_MODEL`）。V1.1 先锁定这一套；后续允许换其他兼容网关，仍不并行接 Claude 原生协议。
- **并行工具调用**：请求参数设 `parallel_tool_calls=False`（网关支持时）。V1.1 **串行执行**工具，即使模型仍一次返回多个 `tool_calls`。部分兼容网关会忽略该参数，引擎仍必须按下一节把**所有** tool 响应写回，否则下一轮会 `400 Bad Request`。
- **熔断（两个独立计数器）**：
  - `max_llm_rounds = 8`：含工具轮与最终回答轮。
  - `max_tool_calls = 4`：一次用户请求内**实际执行**的工具次数；同一 assistant 消息里的 N 个 `tool_calls` 计 N 次。
  - 若本轮 N 个调用会超过剩余配额：执行能执行的，对其余 `tool_call_id` 仍要写回 `role: "tool"`，内容为配额用尽的错误 JSON，不得丢 id。
  - 任一超限：注入说明「已达上限，必须基于已有观察给出总结」，再请求 **1 次无工具** 收尾。禁止静默切断。
- **Prompt 硬规则**（写进 `prompt.py`）：
  - 用户消息里已有 `http(s)` URL → **禁止**先 `search_web`，直接 `scrape_page`。
  - 没有 URL 才 `search_web`，再挑选 1 个最相关结果抓取；确有必要时最多再抓 1 个。
  - 一次只规划一个工具；不要并行点名多个 URL。
  - 工具失败时向用户说明原因，不编造页面内容。
  - 最终回答尽量用 Markdown；列表数据用表格，并保留来源 URL。
- **事件**：引擎只 `yield` 结构化事件，不直接写 HTTP、不直接打终端。引擎必须接受 `asyncio.Event` / `CancellationToken`，在 LLM 读流、httpx、Playwright 等待点检查并退出。

#### 消息组装（违反会 400，必须按此实现）

OpenAI 兼容接口要求：带 `tool_calls` 的 `assistant` 消息之后，必须紧跟与每个 `id` 一一对应的 `role: "tool"` 消息。漏一条、错序、或缺 `tool_call_id`，下一轮请求直接失败。

单轮工具处理顺序：

1. 流式收齐本轮全部 chunk，按 `tool_calls[].index` 拼接 `id` / `name` / `arguments`。
2. 构造并 **append 完整 assistant 消息**（`content` 可为 `null`/空，仍须原样保留 `tool_calls` 数组，含每个 `id`）。不得在此时丢掉这条 assistant。
3. 对每个 tool_call **按原顺序**：
   - `json.loads(arguments)` 失败：不调用 Python；`tool_end(status=error)`；仍 append `role: "tool", tool_call_id, content=错误 JSON`。
   - 成功：先发 `tool_start`（完整 `args` 对象），再执行函数，再 `tool_end`，再 append 对应 `role: "tool"`。
4. 全部 tool 响应写完后，才发起下一轮 LLM。禁止「只回填第一个 tool」。

```
messages = [system, user, ...]
# 本轮模型返回 2 个 tool_calls 时，上下文必须是：
[
  ...,
  {"role": "assistant", "content": null, "tool_calls": [tc1, tc2]},
  {"role": "tool", "tool_call_id": tc1.id, "content": "..."},
  {"role": "tool", "tool_call_id": tc2.id, "content": "..."},
]
```

`tests/test_engine_messages.py` 用 mock LLM 覆盖：单工具、一次返回两个 `tool_calls`、arguments 非法 JSON。断言下一轮 payload 里 tool 响应条数 = `tool_calls` 条数。

#### 流式 tool_calls 与 `tool_start` 时机

流式里 `function.arguments` 是 JSON 碎片（`{"url": "ht` → `tps://..."}`）。这些碎片：

- **不得**当 `token` 发给前端；
- **不得**在碎片阶段发 `tool_start`（前端会拿到非法 JSON，转圈也和真实联网不同步）。

**V1.1 固定用方式 A**：当前轮 stream 结束（`finish_reason` 出现或 iterator 耗尽）→ 拼好每个 `args` → **即将调用 Python 函数的前一刹那** 发 `tool_start({name, args})`。同一轮若先有可见 `content` delta，仍可先发 `token`，再进入工具阶段。

### 模块 C：事件协议（CLI 与 SSE 共用）

所有事件带 `request_id`。Pydantic 定义在 `backend/agent/schema.py`。

| 事件 | 何时发出 | 载荷 | 渲染行为 |
| --- | --- | --- | --- |
| `ping` | 至少每 15s，空闲时也发 | `{"request_id"}` | 忽略；防代理掐连接 |
| `token` | 模型产出可见文本 delta | `{"text"}` | 打字机拼接正文。工具参数流式 delta **不**当 token |
| `tool_start` | 本轮 tool_calls 收齐且对应 `args` 已 `json.loads`，**调用 Python 前** | `{"name","args"}`；`args` 必须是完整对象 | 工具卡片转圈，展示参数 |
| `tool_end` | 工具返回（成功或失败） | 见下表 | 卡片结束；展开只显示 preview |
| `error` | **不可恢复**故障（LLM 挂、内部异常） | `{"message"}` | 轻量告警。工具失败不要走这条 |
| `done` | 每次请求必须最后一条 | `{"status": "complete" \| "error"}` | 结束输入锁与流 |

`tool_end` 固定字段：

```json
{
  "request_id": "…",
  "name": "scrape_page",
  "status": "ok",
  "error": null,
  "preview": "已获取正文约 1500 字。前 800 字预览：…"
}
```

- `status`：`ok` | `error`。
- `error`：失败时的短原因（DNS / 超时 / 4xx / SSRF 拒绝等）。
- `preview`：最多 **800 字符**。完整 `markdown` 只进入 LLM messages，**不进 SSE**。
- 工具失败：发 `tool_end(status=error)`，然后把失败结构化结果交给模型继续；不要发 `error`，除非后续模型也失败。
- 结束语义：有 `error` 事件时 `done.status=error`；否则 `complete`。前端以 `done` 为唯一收尾信号。

Web 传输：`POST /api/chat`，`Content-Type: text/event-stream`。浏览器 `EventSource` 不能 POST，前端必须用 `fetch` + `ReadableStream` 解析 SSE。

请求体：

```json
{
  "message": "用户本轮输入",
  "history": []
}
```

V1.1 `history` 可选。服务端**不持久化**会话；进程内最多保留当前请求的 messages。前端侧边栏历史标为占位，不做本地假历史。

断开取消：客户端取消 fetch / CLI Ctrl+C 时，必须中止**正在进行**的 LLM 流和抓取，而不是把本轮 Agent 跑完。只在 `async for event` 的两次 yield 之间检查 `request.is_disconnected()` **不够**：`scrape_page` 或模型读流会卡住 15s，断开检测要等抓完才触发。

正确分层：

1. **网关**把 `engine.run(...)` 放进 `asyncio.Task`。循环里定期（建议 1s，可与 `ping` 合并）调用 `request.is_disconnected()`；一旦为真，`task.cancel()`，并 `await` 该 task 结束。
2. **生成器退出**时（`CancelledError` / `GeneratorExit` / `aclose()`）走同一条 `finally`：取消 httpx 请求、关闭 Playwright context、若 `done` 尚未发给客户端则不必再推（连接已死），但资源必须释放。
3. **引擎内部**把同一个 cancel scope 传进 LLM 流式读取和 `scrape_page`；`httpx` 用 async 客户端，使 `CancelledError` 能打断 I/O。禁止在事件循环里同步 `time.sleep` / 同步 `requests`。
4. CLI 对 Ctrl+C 同样 `cancel()` 引擎 task，而不是只停打印。

### 模块 D：双端展现层

#### CLI（`cli/main.py`）

- 依赖 Rich。通过 `python -m cli` 启动（保证包导入路径）。
- 直接迭代 `engine.run(...)` 事件：`tool_start` 用 status spinner，`token` 用 Live 刷 Markdown，`tool_end` 打印 name/status/preview。
- 用于秒级排查**逻辑与事件顺序**，不承诺「3 秒出全文」（LLM + 抓页本身更慢）。

#### Web（`frontend/`）

- Next.js App Router + Tailwind。
- V1.1 UI 只做四件套：消息气泡（Markdown / 表格）、工具卡片、输入框、SSE 状态。
- 工具卡片：可折叠；展开显示 `args` + `preview` + `error`，不显示全文。
- 侧边栏可留静态壳，文案写清「V2 再做历史」。
- 第 5~7 天不把视觉仿 Gemini 当作验收条件。

## 4. 四阶段落地步骤

### 阶段一：工具与安全（第 1 天）

1. 虚拟环境安装：`httpx`、`trafilatura`、`markdownify`、`beautifulsoup4`、`pydantic`、`openai`、`fastapi`、`uvicorn`、搜索 SDK。Playwright 可选安装，不作为 Day 1 阻断。
2. 实现 `safety.py`：单测覆盖 `file://`、`http://127.0.0.1`、`http://169.254.169.254/`、正常公网 URL。
3. `scraper.py`：本地 fixture 覆盖（a）普通文章页走 trafilatura；（b）HN 式 `<table>` 列表页在 **不启动浏览器** 时仍能抽出带链接的 Markdown；（c）截断。
4. `search.py`：对真实 API 做一层薄封装；无密钥时测试 skip。

### 阶段二：引擎 + CLI（第 2~3 天）

1. `engine.py`：流式请求；缓冲 tool 参数碎片；`parallel_tool_calls=False`（网关支持时）；按「消息组装」写回 assistant + 全部 tool。
2. `tool_start` 只在 `json.loads` 完整 `args` 之后、Python 函数之前发出。
3. 实现 `max_llm_rounds` / `max_tool_calls`；超限强制无工具总结；多 `tool_calls` 不得丢 id。
4. CLI 消费同一生成器。用例 1 优先打 HN；列表页应走 markdownify 回退，而不是 Playwright。
5. Mock 单测：单工具拼接、一次两个 `tool_calls` 全回填、非法 JSON arguments、熔断后仍有 `done`。

### 阶段三：FastAPI + SSE（第 4 天）

1. `POST /api/chat` → `StreamingResponse`，把引擎事件写成 SSE。
2. 15s `ping`；`request_id`；连接仍在且尚未发送时，`finally` 补 `done`。
3. 引擎跑在 `asyncio.Task` 上；`is_disconnected()` 为真则 `task.cancel()`，等待 finally 释放 httpx/Playwright。用慢 mock 抓取验证：客户端断开后任务在超时上限内结束，而不是跑完整轮。
4. 用 `curl -N` 验证事件顺序，至少覆盖：纯文本、完整 `args` 的 `tool_start`、工具失败后模型解释、`done`。

### 阶段四：Web 联调（第 5~7 天）

1. 初始化 Next.js，消息区 + 输入框 + 工具卡片。
2. `fetch` + `ReadableStream` 解析 SSE；`done` 前锁定输入。
3. 按第 5 节三条用例联调，不以视觉还原度为验收标准。

## 5. V1.1 验收用例

输入一律使用**裸 URL 或纯文本**，不要把 URL 包成 Markdown 链接（避免 href 被替换成搜索页）。

### 用例 1：给定 URL 的抽取

- **输入**：`抓取 https://news.ycombinator.com 首页的前 5 条新闻标题与讨论链接，以 Markdown 表格输出。`
- **期望**：
  - `search_web` 次数 = 0。
  - `scrape_page` 次数为 1 或 2（允许一次失败重试或截断后再抓，禁止先搜索）。
  - **不启动 Playwright**（列表页走 trafilatura 失败后的 markdownify 回退即可）。
  - 前端/CLI 出现工具卡片，随后流式表格，含标题与链接。
- **若 HN 不可达**：改用任意稳定的静态公开列表页，指标不变，仍禁止为列表页启动浏览器。

### 用例 2：搜索 + 抓取

- **输入**：`搜索 Fastify 的官方升级说明，抓取文档站或 GitHub Release 的核心变更，并列出主要 breaking changes。`
- **期望**：
  - 工具顺序为 `search_web` → 至少一次成功的 `scrape_page`。
  - 最终回答有来源 URL，不绑定会过时的具体版本号。
  - 不超过 `max_tool_calls = 4`。

### 用例 3：抓取失败仍优雅结束

分三条跑，都不要包 Markdown 链接：

| 子用例 | 输入 | 期望 |
| --- | --- | --- |
| DNS 失败 | `抓取 https://this-is-a-fake-domain-12345.com` | `tool_end.status=error`，模型说明失败，进程不退出，最后 `done` |
| HTTP 4xx | `抓取 https://httpstat.us/404` | 同上，错误原因可区分 4xx |
| 超时 | 指向一个必然超时的测试 URL（或 mock） | 15s 内失败，不卡死 SSE |

不可恢复错误（如 LLM 密钥无效）才走 `error` + `done.status=error`。

## 6. 相对 V1 的变更摘要

| 项 | V1 | V1.1 |
| --- | --- | --- |
| 循环模型 | 图写 ReAct，代码写 tool_calls | 只保留原生 function calling |
| 熔断 | `max_steps=5` 与「连续工具 5 次」混用 | `max_llm_rounds=8`，`max_tool_calls=4` |
| 工具输出 | 列表字符串 / 纯 Markdown | Pydantic 结构化对象 |
| 抓取引擎 | Day 1 Crawl4AI / Playwright | httpx + 正文抽取，浏览器降级 |
| 安全 | 未写 | SSRF、超时、体积、UA、本机绑定 |
| 事件 | summary 与 UI 全文矛盾；失败语义不清 | `preview` 上限；工具失败走 `tool_end`；必有 `done` |
| CLI | 绕过 FastAPI | 与 Web 共用事件生成器 |
| 模型 | OpenAI / Claude；实现侧常见默认 `gpt-4o-mini` | **当前 MiniMax-M3**（兼容网关）；后续可配其他模型 |
| 搜索 | 主路径 Tavily，DuckDuckGo 兜底 | **当前树莓派 SearXNG**；未配时才 Tavily / DuckDuckGo；后续可配置切换 |
| UI | 仿 Gemini 完整壳 | 消息 + 工具卡片 + 输入 + SSE |
| 验收 | 「只调一次」；假链接指向 Google | 放宽次数；裸 URL；失败分类 |
| 消息组装 | 未写 | assistant 原样入列；每个 `tool_call_id` 都要有 `role: tool`；默认关并行 |
| `tool_start` | 未定义触发点 | 流式拼完 args 后再发，禁止碎片参数 |
| 列表页抽取 | trafilatura 失败就上浏览器 | 少于 200 字符先 markdownify，Playwright 是末档 |
| 断开取消 | 只写了目标 | Task.cancel + 引擎内可中断 I/O，不只在 yield 间轮询 |

按本文件实现即可开工。V1 原文仅作历史对照，以本 V1.1 为准。
