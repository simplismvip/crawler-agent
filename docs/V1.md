# 爬虫 AI Agent (V1 MVP) 开发实施方案

本方案作为 V1 版本的技术设计与落地指引，核心目标是**打通端到端闭环**：验证 Agent 自主决策与工具调用机制，实现状态流式透传，完成基础公开网页的信息检索与结构化抓取。

## 1. 系统总体架构与数据流

整个系统由 **Python 核心服务层**、**通信网关层** 与 **双端展现层（CLI / Web）** 构成：

Plaintext

```
       ┌────────────────────────┐      ┌────────────────────────┐
       │   CLI 调试终端 (Rich)   │      │   Web UI (Next.js 仿Gemini)│
       └───────────┬────────────┘      └───────────┬────────────┘
                   │                               │
            (内部函数直接调用)               (HTTP POST / SSE 流)
                   │                               │
       ┌───────────┴───────────────────────────────┴────────────┐
       │                 FastAPI 通信与路由层                    │
       └───────────────────────────┬────────────────────────────┘
                                   │
       ┌───────────────────────────▼────────────────────────────┐
       │                 Agent 引擎核心循环                      │
       │  - 状态管理 (ReAct: Plan -> Act -> Observe -> Finish)  │
       │  - 上下文历史组装                                        │
       │  - 步数熔断控制器 (Max Steps = 5)                       │
       └──────────────┬───────────────────────────┬─────────────┘
                      │                           │
          [Tool Calling 识别]              [调用底层 Skill]
                      │                           │
                      ▼                           ▼
          ┌──────────────────────┐    ┌─────────────────────────┐
          │  大语言模型 (LLM API) │    │       Skill 执行器       │
          │  OpenAI / Claude 等   │    │  ├─ search_web (搜索)    │
          └──────────────────────┘    │  └─ scrape_page (Crawl4AI)│
                                      └─────────────────────────┘
```

## 2. 核心模块设计与职责

### 模块 A：Skill 工具执行层 (`backend/skills/`)

负责与外部世界交互，要求入参和出参必须强类型化并自动生成 JSON Schema。

- **`search_web(query: str, max_results: int = 3)`**：

- **作用**：获取目标网页的初始 URL。

- **技术实现**：优先接入轻量 Search API（如 DuckDuckGo Search 库、Tavily API 或 Google Custom Search）。

- **输出**：包含 `title`, `url`, `snippet` 的列表字符串。

- **`scrape_page(url: str)`**：

- **作用**：抓取目标网页，清洗并提取核心正文。

- **技术实现**：使用 `Crawl4AI` 或原生 `Playwright` 获取页面渲染后的 HTML，转换为 Markdown，并截断超长无用 DOM（建议上限 4000~8000 Tokens）。

- **输出**：清洗后的 Markdown 文本。

### 模块 B：Agent 核心引擎 (`backend/agent/`)

- **架构模式**：轻量级 ReAct 循环（无需直接引入过重的全家桶框架，可用 Python 原生状态循环或 LangGraph）。

- **步数熔断机制**：单次任务循环上限设为 `max_steps = 5`，超过步数直接强制总结退出，防止死循环。

- **事件回调机制**：Agent 内部执行的每一个动作（生成 Token、调用工具开始、工具返回结果、发生错误）通过统一的异步生成器（Async Generator）对外产出事件。

### 模块 C：通信协议层（SSE 事件格式定义）

前端与后端通过 HTTP POST 建立连接，后端以 `Content-Type: text/event-stream` 返回事件流：

| **事件名称 (event)** | **数据载荷示例 (data)**                                                    | **前端行为**           |
| ---------------- | -------------------------------------------------------------------- | ------------------ |
| `token`          | `{"text": "正在为您"}`                                                   | 打字机效果拼接正文          |
| `tool_start`     | `{"name": "scrape_page", "args": {"url": "https://..."}}`            | 渲染“正在调用工具”卡片（转圈状态） |
| `tool_end`       | `{"name": "scrape_page", "status": "ok", "summary": "已获取 1500 字内容"}` | 工具卡片标记完成，展示结果摘要    |
| `error`          | `{"message": "抓取超时，正在尝试降级回答"}`                                       | 页面展示轻量告警样式         |
| `done`           | `{"status": "complete"}`                                             | 结束当前会话响应状态         |

### 模块 D：双端展现层

- **CLI 客户端 (`cli/main.py`)**：

- 基于 `Rich` 库实现。

- 用 `Console.status` 展示工具调用等待，用 `Live` 或 Markdown 动态打印正文，用于 3 秒内快速排查 Agent 逻辑。

- **Web 端 (`frontend/`)**：

- 技术栈：**Next.js (App Router) + Tailwind CSS + Lucide Icons**。

- **左侧侧边栏**：支持折叠/展开，含“新建对话”按钮和当前历史列表占位。

- **右侧主交互区**：

    - 消息气泡（Markdown 渲染、表格支持、代码块一键复制）。
    
    
    
    - **工具执行卡片**：仿 Gemini 的可折叠面板，展示“⚡ 正在执行 `scrape_page`”，点击可展开看 URL 参数和返回结果。
    
    
    
    - **底部悬浮框**：居中仿胶囊圆角设计，支持多行文本自适应。

## 4. 四阶段落地实施步骤

### 阶段一：工具库封装与本地调试（第 1 天）

1. 创建虚拟环境并安装依赖：`crawl4ai` (或 `playwright`), `duckduckgo-search`, `pydantic`, `openai`。

2. 运行 `crawl4ai-setup` 安装浏览器依赖。

3. 编写 `skills/search.py` 与 `skills/scraper.py`，写单元测试确保传入一个 URL 能稳定返回去除干扰标签后的正文 Markdown。

### 阶段二：Agent 核心循环与 CLI 端跑通（第 2~3 天）

1. 在 `agent/engine.py` 中编写模型交互循环：
- 构造包含工具列表的 Payload 请求 LLM。

- 当 LLM 返回 `tool_calls` 时，解析参数并调用对应 Python 函数。

- 将工具返回值拼接为 `role: "tool"` 消息，重新发起模型请求。

- 增加判断：连续工具调用超过 5 次强制中断。
2. 编写 `cli/main.py`，在控制台跑通 Hacker News 抓取测试，确保终端能正确打印出调用过程和结果。

### 阶段三：FastAPI 服务与 SSE 协议对接（第 4 天）

1. 在 `backend/app.py` 中创建 POST `/api/chat` 接口。

2. 将 Agent 产生的 `token`、`tool_start`、`tool_end` 事件包装为 SSE 规范格式通过 `StreamingResponse` 实时推流。

3. 使用 `curl` 或 Python 简易脚本验证流式输出与事件格式正确无误。

### 阶段四：Web 页面搭建与联调（第 5~7 天）

1. 使用 `create-next-app` 初始化前端项目，配置 Tailwind CSS。

2. 搭建三段式布局：左侧边栏、主对话视口、底部悬浮居中输入框。

3. 编写前端 SSE 监听逻辑（使用 `fetch` + `ReadableStream` 解析 SSE 事件）。

4. 渲染 Tool 执行卡片与最终 Markdown 表格。

## 5. V1 最终验收测试用例

- [ ] **用例 1（单步抓取）**：

- **输入**：“抓取 [https://news.ycombinator.com](https://news.ycombinator.com/) 首页的前 5 条新闻标题与讨论链接，以 Markdown 表格输出。”

- **指标**：Agent 仅调用一次 `scrape_page`，前端展示工具卡片，紧接着流式输出表格。

- [ ] **用例 2（搜索 + 抓取多步链路）**：

- **输入**：“搜索最新的 Fastify 5.0 特性，并抓取官方更新日志的核心内容告诉我。”

- **指标**：Agent 先调用 `search_web`，拿到 URL 后自主调用 `scrape_page`，两张工具卡片依序展开，最终给出总结。

- [ ] **用例 3（容错测试）**：

- **输入**：“抓取一个不存在的网址 [https://this-is-a-fake-domain-12345.com](https://www.google.com/search?q=https://this-is-a-fake-domain-12345.com)。”

- **指标**：爬虫报错被捕获，通过 `tool_end` 传递失败状态，Agent 自主回复说明抓取失败原因，程序不崩溃退出。
