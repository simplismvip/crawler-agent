# 爬虫 AI Agent (V1.2) 插件化 Skills 实施方案

本方案是 V1.1 的下一版。V1.1 已打通：function-calling 循环、SSE、SearXNG + MiniMax、Gemini 浅色壳、SQLite 会话、`httpx + trafilatura + markdownify` 静态抓页。

V1.2 的目标不是再堆一个「全能爬虫」，而是把抓取能力收成 **可插拔 Skill**：模型按**场景**选工具，每种工具内部绑定一种主库。Web UI、会话、模型选择沿用 V1.1，本版不重做壳。

## 0. 范围

### 做

- Skill 注册表：声明、启用/停用、生成 OpenAI tools schema、按名分发。引擎不再写死 `if name == "scrape_page"`。
- 模型只看见**已安装且已启用**的 Skill。缺可选依赖时该 Skill 不注册，避免模型点到会立刻 ImportError 的工具。
- 四个新的场景 Skill（均可选 extras，缺省不装）：
  - `scrape_rendered`：Crawl4AI，动态/JS 页。
  - `download_media`：yt-dlp，音视频与字幕元数据。
  - `download_gallery`：gallery-dl，图集/相册。
  - `scrape_social`：MediaCrawler 适配器，国内社交公开页（无 Cookie 时明确失败）。
- `scrape_page` 保持默认静态快路径；可选把 HTTP 客户端换成 `curl_cffi`（对模型不可见）。
- `GET /api/skills`：列出全部声明的 Skill（含未启用原因、安装命令），便于 Web 置灰与排错。
- 媒体类工具卡片：展示标题、条数、本地路径，不把二进制塞进模型上下文。

### 明确不做（推迟到 V1.3 / V2）

- 登录墙 UI、Cookie 采集向导、绕过 Cloudflare / DataDome / Akamai。
- 把库名直接暴露成工具（`use_trafilatura`、`use_crawl4ai` 这类）。
- Firecrawl 云服务、全站递归 `Crawl All`。
- 多页并行抓取、站点级调度、多用户。
- PDF / Excel 文档 Skill（`pdfplumber`、`openpyxl`）。
- `DrissionPage`、`playwright-stealth`、`Selenium-Base UC`、`Scrapling`、`aiohttp`、`requests-html`、`selectolax`。

### 一条必须先对齐的原则

**模型选的是能力，不是库。**

| 错误 | 正确 |
| --- | --- |
| 15 个库 = 15 个 function，让模型猜用 trafilatura 还是 curl_cffi | 4～6 个场景工具；描述里写「何时用」 |
| `scrape_page` 内部再让模型挑实现 | Skill 内部固定主库；失败时 `error` + `hint` 提示下一个 Skill |
| 没装 Crawl4AI 仍把 `scrape_rendered` 交给模型 | 注册表按 extras 裁剪 tools 列表 |

V1.1 的「抽空就静默上 Playwright」改为：静态工具不再偷偷开浏览器。JS 页由模型在看到 `empty content` / `hint=scrape_rendered` 后显式改调 `scrape_rendered`。这才是「AI 决策」。

## 1. 库取舍

下列取舍以「本机 Agent、公开网页、可测试、依赖可关」为准，不是技术排行榜。

### 1.1 V1.2 采用

| 角色 | 库 | 暴露给模型？ | 理由 |
| --- | --- | --- | --- |
| 静态 HTTP | `httpx`（默认）/ `curl_cffi`（可选 extras `http-stealth`） | 否 | V1.1 已用 httpx。curl_cffi 只解决「Python TLS 握手被拒、但仍是公开页」的静态请求，不作为独立工具。 |
| 文章正文 | `trafilatura` | 否 | 已在用，准确率高。 |
| 列表/目录页 | `markdownify` + BeautifulSoup | 否 | V1.1 已做，HN 这类页必须走这里。 |
| JS / 复杂页 | **Crawl4AI** | 是，作为 `scrape_rendered` | LLM 友好 Markdown、浏览器渲染、异步。这是本版通用主力增强，替代「藏在 scrape_page 里的 Playwright」。 |
| 音视频 | **yt-dlp** | 是，作为 `download_media` | 专门站点抽取，比通用爬虫稳。 |
| 图集 | **gallery-dl** | 是，作为 `download_gallery` | 同上，面向相册/时间线图片。 |
| 国内社交 | **MediaCrawler 适配器** | 是，作为 `scrape_social` | 不是 PyPI 里的一句话依赖，是独立项目。本版做 Skill 接口 + 子进程/适配层；无 Cookie 返回明确错误，不实现登录。 |

默认 `pip/uv` 安装集与 V1.1 相同。Crawl4AI / yt-dlp / gallery-dl / curl_cffi 全部是 **optional extras**。

### 1.2 本版不用

| 库 | 决定 | 原因 |
| --- | --- | --- |
| Firecrawl | 不用 | 托管 API / 全站爬取，和本机单页工具模型不合；密钥与配额会绑死产品形态。 |
| Scrapling | 不用 | 与 Crawl4AI 重叠；抗 DOM 漂移不是 V1.2 验收点。 |
| DrissionPage | 推迟 | 国内隐身浏览器，主题是反检测，和「暂不绕过登录/WAF」冲突；后续若做深度渲染可再评估。 |
| playwright-stealth | 推迟 | 同上，给 Playwright 藏指纹。Crawl4AI 自带浏览器栈，本版不另开隐身插件。 |
| Selenium-Base UC | 不用 | 更重的 UC 兜底，超出本机 MVP。 |
| aiohttp | 不用 | 与 httpx 重复，引擎已是 asyncio + httpx。 |
| requests-html | 不用 | 维护弱，无头能力与 Crawl4AI 重复。 |
| selectolax | 推迟 | 只是解析加速，当前 HTML 体积有上限，测不出收益。 |
| pypdf / pdfplumber / openpyxl / pandas | 推迟到 V1.3 | 文档资产是另一类 Skill，不阻塞本版插件骨架。 |

`markdownify` 已在 V1.1，不必当新工作项。

## 2. 系统架构

```
  CLI / Web
       │
       ▼
  FastAPI（SSE、/api/skills、会话）
       │
       ▼
  Agent 引擎
  - 向注册表要 openai_tools()
  - SYSTEM_PROMPT = 固定规则 + 已启用 Skill 的 routing 段落
  - 按 name 分发，禁止写死工具名分支
       │
       ▼
  Skill 注册表
  ┌────────────┬──────────────────┬──────────────────┐
  │ search_web │ scrape_page      │ scrape_rendered  │
  │ SearXNG    │ httpx/curl_cffi  │ Crawl4AI         │
  │            │ trafilatura      │ （extras.rendered）│
  │            │ markdownify      │                  │
  ├────────────┼──────────────────┼──────────────────┤
  │ download_  │ download_gallery │ scrape_social    │
  │ media      │ gallery-dl       │ MediaCrawler 适配 │
  │ yt-dlp     │                  │ （Cookie 门闸）   │
  └────────────┴──────────────────┴──────────────────┘
       │
       ▼
  共用 safety：SSRF、超时、体积、host 间隔、下载目录沙箱
```

真实循环仍是 V1.1 的串行 function calling：一次只执行一个工具；`max_llm_rounds=8`；`max_tool_calls` 从 4 提到 **6**（静态失败后改调渲染，或搜索后再下媒体，需要多一次）。

## 3. Skill 契约

每个 Skill 是一个模块，导出同一个 `Skill` 对象，禁止在 `engine.py` 里为新工具加 `if`。

```python
class Skill(Protocol):
    name: str                          # function 名
    description: str                   # 给模型的一句话 + 何时用
    input_model: type[BaseModel]
    output_model: type[BaseModel]
    extras: str | None                 # pip extra 名；None 表示默认安装
    routing: str                       # 追加进 system prompt 的 1～3 条规则

    def available(self) -> bool: ...   # 依赖能 import 且配置满足

    async def run(self, args: dict[str, Any], context: SkillContext) -> BaseModel: ...
```

`SkillContext` 由引擎注入，**禁止**放进 `input_model` / OpenAI schema。模型不能也不该填写这些字段：

```python
@dataclass
class SkillContext:
    request_id: str
    cancel_event: asyncio.Event | None = None
```

不要做成 Pydantic model：`cancel_event` 不可序列化，且这组字段永远不进 tools schema。

下载沙箱路径一律 `data/downloads/{context.request_id}/`，由 Skill 内部拼接。`request_id` 出现在 input schema 里视为实现错误。

注册表：

- `backend/skills/registry.py`：收集 builtin 列表，过滤 `available()`，生成 tools schema，`get(name).run(...)`。
- `backend/skills/builtin/`：一文件一 Skill（或现有 `search.py` / `scraper.py` 迁入后由薄包装导出）。
- 新增 Skill = 新文件 + 挂到 builtin 列表。不改引擎。

`engine.default_tool_runner` 变成：

```python
skill = registry.get(name)
validated = skill.input_model.model_validate(args).model_dump()
return await skill.run(validated, context)
```

未知名称 → `tool_end.status=error`，文案 `unknown skill`，不要抛崩整轮。

所有输出继续是 Pydantic。前端 `preview` 仍截断 800 字符。媒体 Skill 的 `preview` 用「标题 + 文件数 + 路径」，不用文件内容。

失败时鼓励带 `hint` 字段（可选，字符串）：例如 `scrape_page` 抽空 → `hint="scrape_rendered"`。`hint` 的值**永远是另一个已注册工具名**，不是给用户看的建议文案。`tool_end.preview` 与聊天气泡不得包含 `hint` 原文；模型只在 `role: tool` 的 JSON 里看到它。

## 4. 各 Skill 规格

### 4.1 `search_web`（已有，迁入注册表）

不变：SearXNG → Tavily → DuckDuckGo。`max_results` 1～5。

### 4.2 `scrape_page`（已有，收窄职责）

**主库：** httpx（或 curl_cffi）+ trafilatura + markdownify。

**本版改动：**

1. **不再调用 Playwright。** JS 壳失败返回 `empty content`，并设 `hint="scrape_rendered"`（仅当 `scrape_rendered` 已启用）。
2. 若 extras `http-stealth` 可用，静态 GET 走 `curl_cffi`（impersonate `chrome`），失败则回退 httpx。模型不可见。
3. 列表页 < 200 字符仍先 markdownify，逻辑保留。

**SSRF 与 DNS 重绑定（httpx / curl_cffi 同样适用）：**  
`validate_fetch_url` 先解析 DNS、校验 IP。随后发请求时**不得再让客户端自行解析一次域名**（V1.1 的 httpx 也有这个窗口）。校验通过后做 IP Pinning：把 `{hostname}:{port}:{validated_ip}` 交给客户端（curl 的 `CURLOPT_RESOLVE` / curl_cffi 的 `resolve`；httpx 则对 pinned IP 建连并保留 `Host` 头与 TLS SNI 为原 hostname）。这样 SNI/指纹仍是域名，TCP 不会被重绑定到内网。只 pin 本次校验通过的地址；失败则整次请求失败，禁止无 pin 回退。

输入输出 schema 与 V1.1 兼容，可加可选 `hint: str | None = None`。

### 4.3 `scrape_rendered`

**主库：** Crawl4AI（`extras.rendered`）。

```python
class ScrapeRenderedInput(BaseModel):
    url: str

class ScrapeRenderedOutput(BaseModel):
    url: str
    title: str = ""
    markdown: str = ""
    truncated: bool = False
    error: str | None = None
    hint: str | None = None
```

- 先 `validate_fetch_url`。
- `AsyncWebCrawler` 抓单 URL，优先 `fit_markdown` / 清洗后 Markdown；空则退原始 markdown。
- 超时 30s（渲染比静态宽）；正文仍截断约 12k 字符 / 4000 tokens。
- 禁止在本工具内递归全站。
- 未安装：`available() is False`，不注册。
- 安装：`uv pip install crawl4ai` 后按上游要求装浏览器（文档写清命令）。单测 **mock crawler**，CI 不下载 Chromium。

**何时用（写入 description + routing）：** SPA、内容由脚本渲染、`scrape_page` 刚返回 empty content。普通文章/文档/HN **禁止**一上来就调这个。

### 4.4 `download_media`

**主库：** yt-dlp（`extras.media`）。

```python
class DownloadMediaInput(BaseModel):
    url: str
    audio_only: bool = False
    info_only: bool = True  # 默认只取元数据/字幕，不落盘音视频

class MediaFile(BaseModel):
    path: str
    media_type: str = ""   # video / audio / subtitle
    bytes: int = 0

class DownloadMediaOutput(BaseModel):
    url: str
    title: str = ""
    extractor: str = ""
    duration: float | None = None
    uploader: str = ""
    description: str = ""
    captions: str = ""     # 字幕或自动字幕纯文本，截断同正文上限
    files: list[MediaFile] = Field(default_factory=list)
    error: str | None = None
```

- SSRF 同样执行。沙箱目录 `data/downloads/{context.request_id}/`。
- **`info_only=True`（默认）：** 只 `extract_info` + 拉字幕/简介，不下载音视频。超时 **20s**。`captions`/`description` 可进模型上下文（截断约 12k 字符）；`files` 为空。
- **`info_only=False`：** 用户明确要求下载/保存到本地时才走。先 `extract_info` 再下载。单文件上限 **200MB**，单次最多 **3** 个文件，超时 **120s**。回给模型的仍是元数据 + 路径，不是二进制。视频优先选 **H.264(avc1)+AAC 的 MP4**，避免站点默认 AV1 在 QuickTime/课件里打不开。
- 不支持登录区视频；需登录则 `error` 说明。

**何时用：** 视频链总结、字幕、标题作者 → `download_media` 且保持 `info_only=True`。只有用户说「下载/保存视频」才设 `info_only=False`。不要为了读简介去 `scrape_page` 视频站播放页（往往是 JS 壳）。

### 4.5 `download_gallery`

**主库：** gallery-dl（`extras.gallery`）。

```python
class DownloadGalleryInput(BaseModel):
    url: str
    max_items: int = Field(default=12, ge=1, le=30)

class DownloadGalleryOutput(BaseModel):
    url: str
    title: str = ""
    files: list[MediaFile] = Field(default_factory=list)
    truncated: bool = False
    error: str | None = None
```

- 图片写入 `data/downloads/{context.request_id}/`。
- 单张 20MB，合计张数夹紧到 `max_items`。
- 单测用假 extractor，不打真实站点。

**何时用：** 图集、相册、时间线多图。不要对普通文章页调用。

### 4.6 `scrape_social`

**主库：** 不 vendor 整个 MediaCrawler 仓库。做 `backend/skills/social/` 适配层：优先调用本机已配置的 MediaCrawler 工作目录（子进程，超时杀掉）；没有安装则 `available() is False`。

```python
class ScrapeSocialInput(BaseModel):
    url: str
    platform: str | None = None  # xhs / dy / wb / bili / … 空则从 URL 推断

class ScrapeSocialOutput(BaseModel):
    url: str
    platform: str = ""
    markdown: str = ""
    truncated: bool = False
    error: str | None = None
```

- Cookie 目录：`data/cookies/{platform}.json` 或环境变量 `SOCIAL_COOKIES_DIR`。
- **没有对应 Cookie：立即失败**，文案与 V1.1 登录墙一致：「当前不能带登录态抓取」，`hint` 指向配置 Cookie 的 README 小节。禁止调 Crawl4AI 去撞登录页。
- 本版不做扫码登录、不做验证码、不做指纹对抗。
- 平台白名单先收：`xhs`、`bili`、`dy`、`wb`。其他 URL 走普通 scrape，不要硬塞社交工具。

若 MediaCrawler 本机未部署，该 Skill 不出现在 tools 里。文档给出可选安装路径，代码用适配器接口，便于以后换实现。

## 5. Prompt 与路由

`SYSTEM_PROMPT` 拆成固定头 + 注册表拼接的 routing。

固定头保留：不编造、一次一个工具、失败说原因、最终 Markdown 带来源。

删除「有 URL 就只能 scrape_page」。改为：

1. 已有 URL 时禁止先 `search_web`。
2. 普通网页 → `scrape_page`。
3. `scrape_page` 返回 empty / `hint` 为某一工具名，且该工具在当前 tools 列表中 → **必须立刻调用该工具**。严禁把 `hint` 原文（例如 `scrape_rendered`）当作对用户的回答。不要未试静态就渲染。
4. 音视频：总结/字幕/简介 → `download_media` 且 `info_only=true`；仅当用户明确要求下载到本地时才 `info_only=false`。
5. 图集 → `download_gallery`。
6. 小红书/抖音/微博/B 站内容页且 `scrape_social` 可用 → 用它，不要用静态抓包登录墙。
7. 工具失败不要假装成功。

固定头须含这一句（原文进 `prompt.py`）：

> 如果工具 JSON 里 `hint` 非空，且其值等于当前可用工具名，你必须在下一步调用该工具。禁止把 hint 或工具名直接输出给用户。

每个 Skill 的 `routing` 字符串只在 `available()` 时拼进去，避免模型看到未安装工具。

## 6. 安全（在 V1.1 之上）

| 规则 | V1.2 |
| --- | --- |
| 协议 / SSRF / 跳转 | 所有出网 Skill 共用 `validate_fetch_url`，含 yt-dlp / gallery-dl / Crawl4AI 入口 URL |
| DNS 重绑定 | 校验后 IP Pinning（Host + SNI 仍用域名）；httpx 与 curl_cffi 都要 pin，禁止校验后再解析 |
| 静态超时 / 体积 | 15s，2MB HTML（与现在一致） |
| 渲染超时 | 30s |
| 媒体超时 / 体积 | info_only 20s；下载 120s，单文件 200MB |
| 下载位置 | 仅 `data/downloads/`，禁止 `..` 逃逸 |
| 不把媒体喂给 LLM | 只回路径与元数据 |
| 浏览器 | 只出现在 `scrape_rendered`；默认环境不装 |
| 反爬套件 | 不进本版 |

`USER_AGENT` 改为 `CrawlerAgent/1.2 (+local)`。

## 7. API 与 Web

- `GET /api/skills` 返回全部已声明 Skill（含未启用），便于 Web 置灰与排错。本版不做用户开关，因此不另设 `enabled`（与 `available` 同义会打架）。字段：

```python
class SkillInfo(BaseModel):
    name: str
    description: str
    available: bool
    extras: str | None = None
    missing_dependency: str | None = None   # 如 crawl4ai
    install_cmd: str | None = None          # 如 uv pip install crawl4ai
    unavailable_reason: str | None = None   # 如 missing extras / no cookies
```

Web 对 `available=false` 的项可 hover：`未启用（缺少 crawl4ai，请执行 uv pip install crawl4ai）`。`unavailable_reason` 覆盖非 pip 原因（社交 Cookie 缺失）。
- SSE 事件 schema 不改。`tool_start.name` 会是新工具名；前端按 name 选图标（Globe / 渲染 / 影片 / 图片 / 社交），未知 name 用通用扳手。
- 媒体 `tool_end.preview` 展示文件列表；不在对话里内嵌播放器（本版不做）。
- 不改侧边栏、模型选择、流式 Markdown。

## 9. 测试与验收

单测必须在**不安装 extras** 时全绿。带 extras 的测试用 mock / monkeypatch import。

| 用例 | 期望 |
| --- | --- |
| 注册表默认 | 只有 `search_web`、`scrape_page` |
| mock 掉 crawl4ai import | `scrape_rendered` 出现在 tools |
| `scrape_page` 对 JS 壳 | 无浏览器调用；`hint=scrape_rendered` 当渲染 Skill 启用时 |
| 引擎分发未知工具 | `tool_end` error，进程不崩 |
| `download_media` schema | input 无 `request_id`；沙箱用 `context.request_id` |
| `download_media` info_only | 默认 True；不写音视频文件；输出含 title/captions |
| `download_media` 下载 mock | `info_only=False` 才写入临时目录 |
| `tool_end.preview` | 不含 `hint` 原文 |
| `download_gallery` 张数夹紧 | `max_items=99` → 30 |
| `scrape_social` 无 Cookie | error 含登录/Cookie，不调用渲染 |
| SSRF | `http://127.0.0.1/` 对新媒体工具同样拒绝 |
| 旧验收 1～3 | HN 表格、搜索+抓取、失败优雅结束 —— 行为与 V1.1 一致（HN 仍走静态 markdownify，不准走 Crawl4AI） |

手工（本机装 extras 后）：

1. 静态博客 / 文档：只出现 `scrape_page`。
2. 已知 JS 壳公开页：先静态失败，再 `scrape_rendered` 出正文。
3. 「这个视频讲了什么」：`download_media` 且 `info_only=true`，数秒内用字幕/简介回答，不落盘 MP4。明确说「下载到本地」才落盘。
4. 未配 Cookie 的小红书：`scrape_social` 或静态失败说明，不编造笔记正文。

## 10. 实现顺序（按此分支开发）

分支名：`v1.2-plugin-skills`（从当前 `main` 拉出）。

1. **注册表 + 迁入现有两工具**，引擎去分支，单测绿。行为与 V1.1 等价，Playwright 末档先删（JS 壳改为 hint）。
2. **`scrape_rendered` + Crawl4AI mock 测试**，prompt 路由，Web 图标。
3. **`curl_cffi` 可选 HTTP 后端**（纯内部；与 httpx 共用 IP Pinning；失败回退 httpx 时仍必须 pin）。
4. **`download_media` / `download_gallery`**，下载沙箱与卡片。
5. **`scrape_social` 适配器 + 无 Cookie 失败**；有 MediaCrawler 时才 `available`。
6. **`GET /api/skills`**、README、本文件勾验收。

每步可单独提交。不要在第 1 步未绿时装 Crawl4AI。
