# V1.3 Login Session Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Attach the user's own login session to existing Skills via a cookie vault and a CLI login helper, without new model-facing login tools or WAF bypass.

**Architecture:** `CookieJar` reads Playwright `storage_state.json` from `data/cookies/`. HTTP/media tools use `cookies[]` (and a tested Netscape transform). `tools.login` polls sentinel cookies then writes storage_state + Netscape. The model still picks Skills; session strategy is bound inside each Skill.

**Tech Stack:** Python 3.12, httpx, yt-dlp, Playwright (login helper), pytest.

**Spec:** `docs/V1.3.md`

## Global Constraints

- Cookie values never appear in tool preview, model JSON, logs, or `GET /api/cookies`.
- SSRF / IP pinning unchanged; cookies do not allow loopback.
- No CDP takeover of daily Chrome. `COOKIES_FROM_BROWSER` default off.
- Login success is sentinel polling, not Enter-to-export.
- Do not commit `data/cookies/` or `data/browser_profiles/` (already under `data/` gitignore).
- Do not add a `login_site` OpenAI tool.
