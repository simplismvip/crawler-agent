# 爬虫 AI Agent (V1.3) 登录态实施方案（讨论稿）

本方案是 V1.2 的下一版。V1.2 已打通：Skill 注册表、`scrape_rendered` / `download_media` / `download_gallery`、社交适配器接口、H.264 兼容下载。`scrape_social` **只做了无 Cookie 失败**，没有真正带登录态出网。

V1.3 的目标不是「破解登录」或「过 Cloudflare」，而是把**用户自己已经登录过的会话**接到现有 Skill 上。模型仍然按场景选工具；有没有登录态是 Skill 内部的门闸。

本文是讨论稿。对齐范围后再写实现计划、再动手。

## 0. 范围

### 做

- **会话仓库（方案 3 的存储契约）**：`data/cookies/` 以 Playwright `storage_state.json` 为平台主文件（Cookie + localStorage），并派生 Netscape 给 yt-dlp / gallery-dl。
- **登录助手（方案 2 的获得路径）**：独立 CLI `python -m tools.login --platform xhs|bili|…`（或以后 Web 的 `/login`）。弹出**专用** Chrome 窗口，人扫码；**以平台关键 Cookie / DOM 特征判定成功**，禁止只靠回车。成功后写出仓库并保留 `data/browser_profiles/{platform}`。
- 把会话注入到已有出网路径（按 Skill 选注入方式，见 §4.3）：
  - `scrape_page`：HTTP Cookie
  - `download_media` / `download_gallery`：cookie 文件；视频可再开 `cookies-from-browser`（方案 1 的安全子集）
  - `scrape_social`：平台 JSON → MediaCrawler
  - `scrape_rendered`：需要登录时挂持久化 profile，不默认每次都开有头浏览器
- 登录墙识别：不能只靠 401/403。必须看跳转 URL（`login` / `passport` / `signin`）和正文/标题特征（见 §4.5）。无会话时禁止改调渲染去撞登录页。
- 安全：Cookie 视为密钥。不进 git、不进 SSE preview、不进模型上下文。

### 明确不做

- **接管日常 Chrome（方案 1 的 CDP `--remote-debugging-port`）**：等于把网银/邮箱会话暴露给本机任意进程，且日常 Chrome 往往已经开着、档案锁死。
- 绕过 Cloudflare / DataDome / Akamai、验证码打码、指纹浏览器套件。
- 把 `--disable-blink-features=AutomationControlled` 等隐身参数做成一等能力（那是反检测，不是登录态）。
- Agent 替用户填密码、自动过短信；模型侧新增 `login_site` 工具。
- 多用户、云端同步 Cookie。
- PDF / Excel Skill（不和登录态抢范围）。

### 一条必须先对齐的原则

**登录态是用户自己的会话；获得方式可以是「文件」或「弹窗扫一次」，运行时按 Skill 选用，不要三套方案互斥单押。**

| 错误 | 正确 |
| --- | --- |
| 所有请求都走持久化 Playwright | 静态页和 yt-dlp 走 Cookie 文件，浏览器只给需要 DOM/签名的站 |
| 所有请求都只注入 Cookie 头 | 小红书 `x-s` 等动态签名靠 MediaCrawler / 浏览器，不靠 httpx 硬注入 |
| CDP 接管你每天用的 Chrome | 专用 profile + 可选 yt-dlp 只读 Cookie 数据库 |
| 新工具 `bypass_login` | 现有 Skill 读仓库；登录是 CLI/人机，不是 function calling |
| 登录成功后一律 headless | 国内社交经常仍要有头或走 MediaCrawler；headless 不作验收前提 |

## 1. 问题分层

| 现象 | 本质 | V1.3 |
| --- | --- | --- |
| 打开就是登录框 / 空壳 SPA | 站点要身份 | 有会话则带上；没有则明确失败 |
| 视频低清晰度 / 年龄墙 / 大会员 | 登录影响媒体权限 | yt-dlp 读仓库或 `cookies-from-browser` |
| 小红书 / 抖音签名头 | App 系动态 token，纯 Cookie 不够 | 登录助手导出 → `scrape_social` / MediaCrawler |
| 滑块、5 秒盾、DataDome | 反爬，不是登录 | **不做** |

## 2. 对三种工业方案的结论

不是「选一个」，是 **按获得 / 存储 / 运行拆开**：

| | 方案 1 CDP 接管日常 Chrome | 方案 2 独立持久化 Profile | 方案 3 Cookie 导入池 |
| --- | --- | --- | --- |
| 本项目角色 | **默认不用**。只吸收其子集：yt-dlp `--cookies-from-browser`（读库，不接管浏览器） | **登录助手 + 渲染/社交运行时** | **所有 HTTP / 下载器的存储契约** |
| 优点 | 日常登过就能用 | 与日常 Chrome 隔离；扫一次可复用 localStorage | 快、无浏览器、和 V1.2 目录一致 |
| 缺点 | 安全面过大；档案锁；Agent 绑死日常浏览 | 每次起浏览器重；headless 对风控站不可靠 | Cookie 过期要更新；搞不定 x-s 一类签名 |
| 适合的 Skill | 仅 `download_media` 可选 | `tools.login`、必要时 `scrape_rendered` | `scrape_page`、yt-dlp、gallery-dl、MediaCrawler 入参 |

**推荐落地（混合，而不是纯方案 2）：**

1. **仓库永远是方案 3。** 没有这个，httpx / yt-dlp 只能被迫全程开浏览器，又慢又脆。
2. **人机登录用方案 2。** `tools.login` 弹专用窗口扫码，结束后 `context.cookies()` 写入 `data/cookies/{platform}.json`（及 Netscape），profile 留在 `data/browser_profiles/`。这比让用户装 EditThisCookie 更符合「本机 Agent」。
3. **方案 1 只留只读 Cookie。** `download_media` 可配置 `COOKIES_FROM_BROWSER=chrome`，**默认关**。macOS 会碰钥匙串授权；Chrome 开着时 Cookie SQLite 常 `Database is locked`。遇此优先用 `tools.login` 导出的 Netscape，禁止文档教用户给日常 Chrome 开 remote debugging。

这样：知乎/普通登录墙走 httpx+Cookie；B 站大会员走 yt-dlp+文件或浏览器 Cookie；小红书走登录助手导出 + MediaCrawler。模型决策链仍然是点 `scrape_social` / `download_media`，不会出现 `login_site`。

### 2.3 模型「按实际情况决策」选的是 Skill，不是方案编号

V1.2 的原则仍然有效：**模型选能力，不选库、不选登录方案。** 若把方案 1/2/3 暴露成 `use_cdp` / `use_profile` / `use_cookie_file` 三个 function，模型会倾向最重的那条（每次开持久化 Chrome），下载视频也会去点浏览器。

正确的决策链（与现引擎相同：`tool_choice=auto`，一次一个工具）：

| 用户意图 / 页面形态 | 模型应调 | Skill 内部绑定的会话方案 |
| --- | --- | --- |
| 已有视频 URL，要文件或大会员清晰度 | `download_media` | 仓库 Netscape（方案 3）；可选 `cookies-from-browser`（方案 1 子集） |
| 图集 | `download_gallery` | 方案 3 文件 |
| 小红书 / 抖音 / 微博内容页 | `scrape_social` | 方案 3 的平台 JSON + MediaCrawler（App 接口，见 §2.4） |
| 普通文章，可能要登录 | `scrape_page` | 方案 3 注入 Cookie；登录墙则失败，不 hint 渲染 |
| 公开 JS 壳、不是登录框 | `scrape_rendered` | 通常无登录；不要为了登录去渲染 |
| 工具返回「需要登录」且仓库是空的 | **不要再调抓取** | 回答里请用户跑 `tools.login`（方案 2，人机，不是模型工具） |

Skill 内部还可以做**短策略**（对模型不可见）：例如 `download_media` 先 cookiefile，没有再看环境变量 `COOKIES_FROM_BROWSER`。这是代码绑定，避免模型猜。

失败时用现有 `error` + `hint`：`hint` 只允许是**另一个已启用 Skill 名**（如空壳页 → `scrape_rendered`），或文档锚点 `cookies`。禁止 `hint=scheme_2`。

### 2.3.1 为什么不必「先登录才能知道用哪种工具」

这不是先登录、再看见页面、再决定 Skill。分类依据在**出网之前**就有了：用户原话 + URL 的 host/path。登录只给**已经选中的那条路径**补会话。

```text
用户消息 + URL
        │
        ▼
模型选 Skill（和现在一样，不需要登录）
  下载 /watch /video/BV → download_media
  小红书/抖音/微博内容页 → scrape_social
  其它网页 → scrape_page（空壳且非登录框再 hint scrape_rendered）
        │
        ▼
该 Skill 向 CookieJar 要这个 host 的会话
        │
        ├─ 有 → 带上，执行
        └─ 无 / 仍是登录墙
                │
                ▼
           error「需要登录」
           平台从 URL 推断（xhs/bili/…），不是从登录后的 DOM 推断
           用户跑 tools.login --platform <已推断>
           下一轮对话再调【同一个】Skill
```

| 误区 | 实际 |
| --- | --- |
| 先打开浏览器登录，才能看出这是视频还是文章 | `bilibili.com/video/BV…` + 「下载」已经决定是 `download_media` |
| 登录方案要等页面形态才能选 | 方案跟着 Skill 绑死：媒体=Cookie 文件/from-browser，社交=JSON+MediaCrawler，普通页=HTTP Cookie |
| 登录墙之后要换一套更强的登录方案 | 同一 Skill 补会话再试；Cookie 过期就再跑 login。只有「普通页其实是社交站」才换 Skill（host 已能判断，或 `hint=scrape_social`） |
| 不让模型选方案 = 不让模型选工具 | 模型照样选 `download_media` / `scrape_page` / `scrape_social`。不选的是 CDP vs Profile vs 文件 |

因此 **V1.3 没有「登录 Skill」**，也没有「先 login 再观察该用哪个抓取工具」的步骤。人机登录是仓库的补给，发生在对话外（CLI），或作为失败后的用户动作，而不是 function calling 的第一跳。

### 2.4 除这三套以外还有哪些方案

工业上还能看到下面这些。本版**只把「站点官方 API / App 适配器」算进混合架构**（已经是 `scrape_social`），其余不进 V1.3。

| 方案 | 原理 | 相对 1/2/3 | V1.3 |
| --- | --- | --- | --- |
| **站点官方 API** | YouTube Data API、部分开放平台 token | 最干净，覆盖面窄 | 不作为通用路径；某站真有钥匙再单开，不当登录框架 |
| **App / 移动端接口适配**（MediaCrawler、自研签名） | 模拟 App 请求，Cookie + 设备签名 | 国内社交真正能用的路径；不是「再开一个浏览器」 | **已在混合里**：`scrape_social`。login 助手只负责把网页登录态导出给它 |
| **扫码协议轮询** | 自己生成二维码、轮询登录接口，无人看浏览器 | 比方案 2 更「全自动」，等于逆协议 | 不做。继续用人在真窗口里扫 |
| **Computer-use / Browser-Use** | 多模态模型点登录按钮、输密码 | 方案 2 的加重版 | 推迟。本机 Agent 成本高、不可复现 |
| **抓包自己的流量**（mitmproxy） | 从你手机/电脑拷会话 | 和方案 3 同类，更侵入 | 不做默认路径 |
| **Cookie / 账号市场、住宅代理解锁** | 买别人的登录态或过盾 | 法律与滥用风险 | **明确禁止** |
| **打码平台、指纹浏览器、UC 模式** | 反爬对抗 | 不是登录态 | V1.2 已推迟，V1.3 仍不做 |
| **Firecrawl / Bright Data Unlocker 等云解锁** | 把反爬外包 | 绑云账号与配额 | V1.2 已排除 |
| **真实手机农场**（scrcpy / Airtest） | 真机 App | 重资产 | 不做 |

所以「还有没有更好的第四条主路径」：**有，而且已经选了——国内社交走 MediaCrawler 适配，而不是再发明第四套浏览器方案。** 对 B 站/YouTube 下载，没有比 yt-dlp + Cookie 更合适的通用解。

### 2.1 人机登录工作流（方案 2，仅登录助手）

**禁止「回车即视为已登录」。** 用户常在手机尚未点确认时回车，导出的是游客 Cookie，后续全站失败且极难排查。

```text
用户或你先跑:  python -m tools.login --platform xhs
        │
        ▼
有头专用 Chrome（user-data-dir=data/browser_profiles/xhs）
        │
        ▼
终端：请在窗口扫码。脚本轮询登录态（关键 Cookie / DOM），不要只等回车
        │
        ├─ 检测到平台哨兵 Cookie（见下表）
        │     提示「检测到登录态，正在导出」
        │     写出 storage_state.json + Netscape
        │
        └─ 超时仍无哨兵 / 用户强行回车但 Key 缺失
              告警「未检测到有效登录特征，是否重试？」
              默认不覆盖已有的有效文件
        │
        ▼
之后普通对话只读仓库，不自动再弹窗（避免 SSE 里卡 input()）
```

平台哨兵（可随实现微调，但必须有表、必须单测假 Cookie 判失败）：

| 平台 | 至少具备 |
| --- | --- |
| xhs | `web_session`（仅有设备指纹 `a1` 不算登录） |
| bili | `DedeUserID` **且** `SESSDATA` |
| zhihu | `z_c0` |
| dy / wb | 实现时在本表补一行，禁止无表就导出 |

轮询间隔约 1s，总超时建议 3～5 分钟。回车只表示「我放弃等待、请立即检查当前快照」：检查失败则告警，不把游客态写成成功。

过期时：**再跑一次 login 助手**，或抓取失败文案提示去跑。不在 `POST /api/chat` 里 `input()`。

Web 若以后要 `/login`：后端启动有头浏览器（本机才能看见窗口），用 SSE/`login_required` 事件通知前端「请到弹出的窗口完成登录」，成功判定同样走哨兵 Cookie，而不是把 Playwright 塞进模型工具循环。

### 2.2 明确拒绝的「纯方案 2 MVP」细节

- **不要**把「已登录 → headless 快抓」写成验收标准。小红书/抖音无头经常直接掉登录。
- **不要**把 Crawl4AI 每次 `scrape_rendered` 都挂同一个巨大 default profile。按平台分目录，避免 Cookie 串站。
- **不要**在 V1.3 把隐身参数当默认启动项。真 Chrome `channel="chrome"` 可以要；自动化特征抹除放到以后单独讨论。

## 4. Cookie 仓库契约

默认根目录：`data/cookies/`，`COOKIES_DIR` 覆盖；`SOCIAL_COOKIES_DIR` 作别名。

Profile 根目录：`data/browser_profiles/`（同样在已 ignore 的 `data/` 下）。

### 4.1 格式

平台主文件：`data/cookies/{platform}.json`，采用 Playwright **`storage_state.json`**（`cookies` + `origins[].localStorage`）。国内很多站把设备指纹、UID、签名密钥放在 localStorage，只抽 Cookie 会「带了登录态仍设备异常」。

```json
{
  "cookies": [ { "name": "web_session", "value": "…", "domain": ".xiaohongshu.com", "path": "/", "httpOnly": true, "secure": true, "sameSite": "Lax", "expires": 1735689600.0 } ],
  "origins": [
    {
      "origin": "https://www.xiaohongshu.com",
      "localStorage": [ { "name": "…", "value": "…" } ]
    }
  ]
}
```

谁读哪一层：

| 消费者 | 读取 |
| --- | --- |
| httpx / curl_cffi | 仅 `cookies[]`，按请求 host 过滤 |
| yt-dlp / gallery-dl | 由 `cookies_json_to_netscape()` 生成的旁路文件 `data/cookies/{platform}.netscape.txt` |
| Playwright / 可选 `scrape_rendered` | 整份 `storage_state` 或 profile 目录 |
| MediaCrawler | **默认只喂 `cookies[]`**（多数适配器没有 localStorage 槽）。若某平台仍判设备异常，走浏览器 profile / 适配器扩展，不假装 JSON 里的 origins 已被 MediaCrawler 加载 |

login 助手一次写出：`storage_state` 主文件 + Netscape 派生文件。用户不必维护两份。

### 4.2 查找顺序

平台 `storage_state`（`xhs.json`）→ host 文件 → 整包 Netscape 按 domain 过滤。

### 4.4 Netscape 转换（必须单测）

Playwright `cookies[]` 是 JSON（`sameSite`、`httpOnly`、`secure`、`expires` 浮点）。yt-dlp / gallery-dl 要 **Netscape cookies.txt**：`# Netscape HTTP Cookie File` 头、制表符 7 列、HttpOnly 域名为 `#HttpOnly_.example.com`、过期时间为整型 Unix 秒。

实现：`backend/skills/cookies.py` 中的 `cookies_json_to_netscape()`（不要塞进 `safety.py`）。格式错一点 yt-dlp 会**静默忽略整文件**、当成未登录。

单测至少覆盖：HttpOnly 前缀、`expires` 浮点→整数、`sameSite` 不出现在 Netscape 列、空列表仍写出合法文件头。

### 4.5 登录墙识别（状态码不够）

国内站未登录时经常仍是 **HTTP 200**：JS 跳到 `/login?redirect=`，或遮罩 `<div class="login-modal">` 把正文截断。只认 401/403 会把登录表单当正文喂给模型。

在 `scrape_page` 抽正文**之前**判定，命中则 `error="需要登录"`，**不要** `hint=scrape_rendered`。

判定（按序，高置信才算）：

1. 最终 URL 含 `/login`、`/passport`、`/signin`、`/account/login`（含 redirect 后）。
2. 标题含「登录」「掃碼登錄」「验证码」（整词，注意繁简）。
3. 抽取前 HTML / 可见文本前 500 字含高置信短语，例如：「请先登录后查看完整内容」「登录解锁全文」「登录后即可查看」。

**防误报：** 页脚「登录」链接、导航「登录/注册」、评论区「登录后发表」**单独出现不算**登录墙。必须是「正文被挡」类短语，或 URL 已落到登录路径。不要用「登录」单字全局匹配（前端曾经把「需要登录」误伤过正常 Markdown）。

### 4.3 注入方式（按 Skill）

| Skill | 运行时 | 会话从哪来 |
| --- | --- | --- |
| `scrape_page` | httpx / curl_cffi | CookieJar |
| `scrape_rendered` | Crawl4AI | 能设 cookies 则设；登录墙站点优先改走 `scrape_social` 或提示去 `tools.login`，不默认每次持久化上下文 |
| `download_media` | yt-dlp | 派生 Netscape `cookiefile`；可选 `COOKIES_FROM_BROWSER`（默认关，见钥匙串/文件锁） |
| `download_gallery` | gallery-dl | cookie 文件 |
| `scrape_social` | MediaCrawler | 从平台 `storage_state` 取 `cookies[]`；无有效哨兵则 V1.2 原文案。origins/localStorage 默认不喂给 MediaCrawler |

SSRF、IP Pinning、超时、体积上限不变。带 Cookie **不放宽** 内网限制。

## 5. 失败与 Prompt

固定头追加：

> 工具报「需要登录」或「当前不能带登录态抓取」时，说明原因并告知用户运行 `python -m tools.login --platform …` 或放入 Cookie 文件。禁止建议日常 Chrome 开远程调试，禁止改调 scrape_rendered 去撞登录页，禁止编造登录后正文。禁止把「用方案 2 / 开 CDP」这类实现细节说给用户。

`scrape_page` 判定登录墙：`error` 含「需要登录」，不要 `hint=scrape_rendered`。

## 8. 待讨论问题（已收敛一部分）

已倾向：混合架构；不做 CDP 接管；不做隐身套件；login 不是模型工具。

仍需拍板：

1. **验收站点顺序：** 建议先 **B 站/YouTube 登录下载（Cookie 或 cookies-from-browser）** + **小红书 login 助手导出 JSON**（有 MediaCrawler 才真抓）。知乎类通用页随后。
2. **`COOKIES_FROM_BROWSER`：** V1.3 作 `download_media` 可选环境变量，**默认关**。README 必须写明：macOS 会弹出钥匙串要锁屏密码；日常 Chrome 开着时常见 `Database is locked`。遇此请用 `tools.login` 导出的 Netscape，不要开 CDP。CI 禁止开这个变量。
3. **MediaCrawler：** 无安装时仍 `available() is False`；有安装 + 有 JSON 才出网。login 助手不依赖 MediaCrawler。
4. **过期：** 失败文案提示再跑 `tools.login`，不做主动过期扫描。

## 9. 建议验收（草案）

单测（无真实号、不打真登录站）：

| 用例 | 期望 |
| --- | --- |
| 无 Cookie 的登录墙 URL | error 含登录/Cookie，不调渲染 |
| 假 Cookie 文件 | `resolve(url)` 命中；httpx mock 带 Cookie 头 |
| preview / 模型 JSON | 无 Cookie 值 |
| SSRF | 带 Cookie 也不能打 `127.0.0.1` |
| `download_media` | 配置 cookiefile 时 opts 含路径 |
| `tools.login` 无哨兵 Cookie | 不得写出成功文件；告警未登录 |
| `cookies_json_to_netscape` | HttpOnly 前缀与整数 expires；yt-dlp 可解析（可用文本断言，不真下） |
| 登录墙 200 + 标题「请登录」 | `error` 含需要登录，无 scrape_rendered hint |
| 正文里仅页脚「登录」 | **不**算登录墙 |

手工：

1. 未登录小红书：失败说明，不编造。
2. `tools.login --platform xhs`：未扫完就回车必须告警；扫完后出现含 `web_session` 的 `storage_state` 与 Netscape（仅有 `a1` 不算登录）。
3. 有 MediaCrawler 时笔记正文不是登录页；没有则适配器错误，而不是假装成功。
4. yt-dlp 带派生 Netscape；对话里无 Cookie / localStorage 原文。
5. 知乎类 200 登录墙页：error 需要登录，不把登录表单当正文。

## 10. 实现顺序（对齐后再拆任务）

分支：`v1.3-login`。

1. CookieJar + `storage_state` 读写 + `cookies_json_to_netscape` 单测。
2. `scrape_page` 注入 + **内容特征**登录墙判定。
3. `download_media` / `download_gallery` cookiefile；可选 from-browser（文档写明钥匙串与文件锁）。
4. `tools.login`：持久化 profile、**哨兵 Cookie 轮询**、导出 storage_state + Netscape。
5. `scrape_social` 从 storage_state 取 `cookies[]` 交给适配器。
6. L1 状态接口；README。

不要在第 1 步未绿时接真站或隐身参数。
